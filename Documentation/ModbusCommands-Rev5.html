02 · The registry

System Device List, twelve columns

Stored on the T3 devices themselves, so a replacement PC rebuilds it from the hardware. The tree, Control Basic, the Modbus commands and the poll dialogs all read the same rows.

ColumnMeaningWhat Modbus takes from it
Mainmain-net item, or the parent panel of a sub-net rowroute — the panel the frame is sent to
Sub Netsub-net item name; blank on a main-net rowgrouping only
Serial IDdevice serial numberidentity, diagnostics
Product NameVAV box, T3-BB, power meterdisplay, default name suggestion
Statusonline / offlinean offline row returns -5 without a frame
Product IDmodel idunit-id source when Address is blank
Addresssub id, or unit id on a main-net rowunit id in the MBAP / PDU header
IP Addressmain-net rows only; blank on sub-net rowsTCP host, port 502 unless overridden
Baud9600 … 115200RS485 attempt speed
ParityN / E / O with stop bitsRS485 framing
ProtocolBACnet/IP, Modbus TCP, Modbus RS485which transport a command uses
Panel Name (CBasic)the device’s own panel name, 20 charactersthe device argument of every command
Blank IP on a sub-net row is correct. The IP belongs to the panel the device hangs off; the sub id in Address plus Protocol / Baud / Parity is what identifies and reaches it. A Modbus command needs no IP for such a device.

03 · Panel names

The one address every command uses

RuleDetail
ShapeVAV101, AHU2-3, Meter1 — letters, digits, dash, underscore; at most 20 characters
Source of truththe device. The list shows the name as it stands; there is no PC-side rename
Uniquenesscase-insensitive within one project; a duplicate is rejected on save
No dots, no colons1.2.VAV101 and VAV101:502 are both rejected — the transport is not part of the name
ReservedREG, COIL, DI, IR, AI, AV, AO, BI, BO, BV, MSV, MB_*
Rename on the devicethe program follows, because the name is looked up at run time
Not foundMB_ERR_NO_DEVICE (-5) plus the closest match — never a silent zero

05 · Examples

1 · Register read — FC 0x03

Read one holding register from the device the list calls VAV101 (panel 1, sub id 2). Same frame on the wire, only the spelling changes.

Today
40 VAR100 = 1.2.MB_REG7
Rev5
40 VAR100 = MB_READ("VAV101", REG, 7)

2 · Register write — FC 0x06

A write stops being a left-side assignment and becomes the same verb as read.

Today
230 1.2.MB_REG3 = VAR1 / 65536
Rev5
230 MB_WRITE("VAV101", REG, 3, VAR1 / 65536)

3 · Coil and discrete reads — FC 0x01 / 0x02

Coil reads already worked; the write half of that area is missing today and arrives with this set. A write to a discrete input is rejected in the editor and returns MB_ERR_AREA at run time.

Today
120 VAR107 = 1.2.MB_COIL7
130 VAR108 = 1.2.MB_DISINPUT7
Rev5
120 VAR107 = MB_READ("VAV101", COIL, 7)
130 VAR108 = MB_READ("VAV101", DI, 7)

4 · Float and block — FC 0x03 / 0x10 / 0x0F

Four float spellings collapse into a type and an order argument. Block reads cap at the 125-register specification limit; block writes at 123, with the legacy 25-value ceiling kept for MB_BLOCKWRITE only.

VAR100 = MB_READ ("VAV101", REG, 33, 2, F32, ABCD)   // replaces MB_REG_FLOAT_ABCD33
VAR1[] = MB_READ ("VAV101", REG, 100, 5)               // block read, five registers
MB_WRITE("VAV101", REG, 100, 10, 20, 30, 40, 50)           // FC 10
MB_WRITE("VAV101", COIL, 0, 1, 0, 1)                    // FC 0F - no keyword exists for this today
STA    = MB_LAST_STATUS()                                // 0 ok, -1 timeout, -5 no device or offline

5 · Main-net meter, and a device with no row

199.4. reached the meter by the last octet of its IP. In the list the meter has a panel name and a Protocol of Modbus TCP, so the command names it. A gateway that has never been scanned has no row, so it is defined inline — the one surviving use of MB_DEFINE_DEVICE.

Today
259 VAR98 = 199.4.MB_REG55
Rev5
259 VAR98 = MB_READ("Meter1", REG, 55)
MB_DEFINE_DEVICE("ShopMeter", "TCP:192.168.0.44:502,TO=500,RT=2")
VAR_E = MB_READ("ShopMeter", REG, 300, 2, F32, ABCD)

06 · How a name resolves

MB_READ("VAV101", REG, 7) → System Device List, column Panel Name (CBasic), case-insensitive exact match → row: Main = ctl-1, Sub Net = VAV group, Address = 2, Protocol = Modbus RS485, Baud = 115200, Parity = N → transport = Modbus RS485 on the panel named in Main, unit id = Address → panel ctl-1: IP from its own row, port 502, MBAP unit id 2, PDU → FC 03, address 7, count 1

Resolution order: a row whose panel name matches; then an inline MB_DEFINE_DEVICE handle; then the legacy panel.slave. prefix or IP:<octet>.<unit> token, resolved to a row if one matches, otherwise treated as unregistered.

07 · Per protocol behaviour

Protocol in the rowHostUnit idNotes
Modbus TCPIP Address, port 502Address, else Product ID, else 1main-net device, one TCP frame, no routing
Modbus RS485none — routed through the panel named in MainAddressframing from Baud and Parity; blank IP is expected
BACnet/IPIP Address–the main-net default; a Modbus command against such a row is refused with MB_ERR_AREA, never silently re-routed
offline row (Status)––returns -5 without opening a socket, so a dead device cannot stall a program
Move VAV101 from the RS485 subnet onto its own Ethernet adapter, rescan: the row’s Protocol becomes Modbus TCP with an IP, and not one program line changes.

08 · What the list must guarantee

RequirementWhy the commands need it
Panel name unique per project, case-insensitive, 20 charactersit is the device argument of every command
Sub-net rows keep IP Address blanknobody can hard-code a panel IP into a device that has none
Protocol reports what the device is actually set topicks TCP or RS485 routing instead of an assumption
Baud and Parity sit on the sub-net rowthe RS485 attempt is built from the row, not a global setting
Offline rows keep red status and grey backgrounda command against them returns -5 locally, at no cost on the wire
Modbus rows cached before delete, Undo (n) restores thema mis-delete cannot break programs
Current row highlighted bluethe row being edited is never confused with a bad one

09 · Types, byte order, method

Types

TypeRegistersMeaning
U161unsigned 16-bit, default
S161signed 16-bit
U322unsigned 32-bit
S322signed 32-bit
F322IEEE-754 single
BIT1one bit, bit=<0..15>

Order tokens ABCD, CDAB, BADC, DCBA; BE and LE stay as aliases.

Method of operation

MB_READ (device, area, address [, count]
         [, type [, order]])
MB_WRITE(device, area, address,
         value | value_list [, type [, order]])

FC from area and direction: REG read 0x03 / write 0x06 / block 0x10, COIL read 0x01 / write 0x05 / block 0x0F, DI 0x02, IR 0x04. Limits 125 registers per read, 123 per block write, 2000 bits per read, 1968 coils per block write.

10 · Migration

PhaseWorkExit condition
P0new verbs as translations onto the existing DLL calls; legacy keywords untouchedevery new command produces the same bytes as its legacy pair, verified with the _log exports
P1panel-name lookup over the System Device ListMB_READ("VAV101", …) and 1.2.MB_REG7 reach the same unit with byte-identical traffic
P2type system and byte order in one placeeight float keywords become two aliases, no * 65536 + advice left
P3coil and discrete areas, single and block writesa program can drive a coil and read a discrete input through the same verb
P4Protocol drives transport, offline rows short-circuita TCP row and an RS485 row are reached by the same verb; an offline row costs no socket
P5collapse _2, _nocretical, _tap onto one entry pointone implementation per function code
P6docs and UIthis document replaces the forum write-up; the register tool shows the resolved row, protocol and last status

11 · Open decisions

  1. Unit id when Address is blank on a main-net Modbus TCP row — fall back to Product ID (assumed here) or force an edit.
  2. Array return for block reads, or a separate call name — the program engine has no array type.
  3. A panel-name rename on the device: keep a PC-side alias for programs written against the old name, or follow the device with no alias at all.
  4. BIT as a type or as an operator on a value.
  5. Whether diagnostics 0x08 and exception status 0x07 are in scope.
  6. Auto-splitting oversized blocks, or always MB_ERR_RANGE.
